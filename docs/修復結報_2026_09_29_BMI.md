# 測試流程修復與 BMI 範例交付

## 直接結論

BMI 的直接障礙不是單檔或函式太簡單，而是測試工具沿用車輛專題綁定的初始化設定，在開始生成測試前就拒絕執行。本次修正專案切換時的設定選用，也修正車輛批次已證實的 Mock 誤擋、Reviewer 錯誤意見與局部修復格式問題。

## 修復內容

| 問題 | 修正後行為 | 保留的限制 |
| --- | --- | --- |
| 其他專案的初始化設定擋住 BMI | 按實體根目錄選取；不同根的設定保留但不套用，舊專案不存在也不會阻擋 | 同根過期來源、非法路徑、未模擬的副作用仍受阻；不自動批准新設定 |
| 全檔案執行失敗仍顯示「執行完畢」 | 顯示流程錯誤／受阻數，函式結果以各自報告為準；取消不顯示正常結束 | 流程結束不等於測試或完整品質通過 |
| `_connect` 的有效測試被拒絕 | 支援已證明為標準 Mock 回傳子物件的無參數設定呼叫，繼續尋找後續真實目標與父 Mock 斷言 | 被測試自行呼叫過的子 Mock 及其別名不能充當目標行為證據；任意呼叫保持拒絕 |
| Reviewer 把依賴 patch 當成目標 patch | 比較明確目標與來源依賴使用點，拒絕相矛盾的 finding；標準 patch 匯入行也不能證明非法 patch | 整份錯誤審查維持未完成，不冒充審查通過；自然語言仍須搭配工具驗證 |
| Bug Fixer 回覆多了說明／class 包裝 | 擷取唯一 Python 區塊；只去除與原類別一致且僅含唯一失敗方法的包裝，記錄正規化 | 多區塊、額外方法、fixture／decorator／class 修改仍拒絕；合併後必須再通過 AST 範圍及隔離執行 |
| 依賴範例污染與格式分類不明 | 不再僅因 SQLite 匯入而注入無關 SQL 範例；明示目標匯入、Mock 消費鏈、相依與目標回傳的差別；格式失敗分類正確 | 不保證模型每次生成正確；保留來源、執行證據和提示預算，不靠加重試或降低品質門檻 |

匯入設定作用域的修正由單函式／全檔案、專案預檢、初始化精靈與環境預檢共用。切回原根目錄仍能使用原設定；本次沒有修改原車輛專題或原本的 bmi.py。

## BMI 專案

位置：[examples/bmi](../examples/bmi/README.md)。只用 Python 標準庫。

- `src/bmi.py`：數值驗證、BMI 計算、分類、報表四個純函式。
- `main.py`：命令列入口，匯入時不執行。
- `tests/test_bmi.py`：8 個測試方法，含邊界、無效型別、非有限值、數值超限與四捨五入順序。

在 BMI 專案資料夾執行：

```powershell
python main.py 60 170
python -m unittest discover -s tests -v
```

工具操作：選擇 `examples/bmi` 專案，驗證目標選「執行驗證」，先選 `src/bmi.py` → `calculate_bmi`，再擴大至全檔案／all。不要把身高公分改當公尺輸入。BMI 本身不需要初始化替身或第三方套件安裝。

## 驗證證據

- BMI 內附測試 8／8；命令列 60 公斤、170 公分輸出 BMI 20.76。
- BMI 整合回歸從真正的全檔案指令探索四個函式，經 AST、匯入預檢、結構／binding 檢查、隔離 runner 和 source/test/run 證據核對後通過；保留其他專案設定且未修改來源。
- 車輛六個局部重放全部通過結構、binding 與隔離 runner，皆觀察到真實目標；原先誤擋的 `_connect` 原產物現在也通過。原專題的來源雜湊前後一致。
- 原 Reviewer 回覆重放被拒絕，不再交 Writer 移除合法依賴 patch。回歸包含拒絕審查後仍保存可執行基線、不假冒完整通過。
- 唯一區塊／單方法包裝復原經真實 Python 範圍 gate；fixture、額外方法、簽名衝突與多區塊反例仍受阻。正式 full 流程也驗證格式正規化後的候選能執行，未達品質門檻仍保留未完成狀態。

## 交付邊界

整合回歸使用固定的模型回覆替身驗證工具流程，不代表實驗室模型的生成能力已驗收。實驗室仍須更新版本後實際重跑；需要完整品質時依然必須通過原 coverage、mutation 與 Reviewer 政策。未支援的複雜 Mock 寫法和修復包裝仍可能被拒絕，不能直接改成通過。

工作區原先未提交的型態分析／輸入規劃改動保留原狀，交付驗證使用排除該批改動的乾淨副本。未搬移或改名既有結果。
