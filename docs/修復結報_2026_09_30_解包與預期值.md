# 解包辨識與預期值計算修復結報

## 問題與結果

實驗室結果 `bmi_2026_09_30_12_45` 中，Writer 使用合法的 `bmi, status = calculate_bmi(...)`，但文字檢查只支援單一變數接收，誤判沒有驗證回傳值。該候選另外有四個 BMI 數值與一個狀態預期錯誤。

本次修復工具的語法辨識及執行驗證修復流程，保留原被測專題。以原候選重播完整命令，成功先執行並呈現四個失敗，再修正五個預期常數並重新執行通過。另加一個原已通過案例，證明修復後仍保留該案例。

## 一、Python AST 辨識回傳值

- 正式流程的 TypeScript 預檢將回傳值／斷言關聯交由 Python AST 檢查。
- 支援 tuple／list 解包、巢狀與多行寫法、匯入別名、索引，以及常見結果形狀檢查。
- 同時檢查結果被覆寫、無關的常數斷言、目標與自身比較；既有目標 mock 與危險操作檢查保留。
- 無法建立行為證據時，錯誤附上測試方法及行號；沒有跳過正式 AST、binding、簽名與 runner。
- AST 是有限的靜態分析，複雜動態流程仍可能需要改寫測試或補充支援，不能據此宣稱支援所有 Python 寫法。

實作：`python_scripts/target_result_evidence.py`、`validate_test_bindings.py`、`src/validation/generatedTestValidator.ts`。

## 二、依來源計算常數，再驗證修復

新增 `python_scripts/repair_source_expectations.py`。僅在執行驗證模式已有真實 unittest 斷言失敗時嘗試：

1. 解析原始碼與失敗測試，讀取明確的 literal／fixture 輸入；不匯入或呼叫被測函式。
2. 在限制步數、數值、指數、文字與容器大小的 AST 子集中計算四則運算、`round`／`abs`、比較分支與回傳欄位。
3. 只替換失敗方法的 `assertEqual`／`assertAlmostEqual` 預期參數。輸入、fixture、方法名稱、斷言種類、精度與其他案例均保留。
4. 同步核對所有回傳欄位，因此可處理第一個失敗斷言遮住的後續狀態錯誤。
5. 保存 `arithmetic_001.json`，含來源及測試雜湊、方法／行號、輸入、計算步驟、分支、修正前後值。
6. 候選仍計入修訂與總預算，重新做結構檢查、真實目標執行、隔離驗證及已通過案例保留檢查；失敗不能計入通過。

此能力有意限制範圍：外部相依、未知輸入、迴圈、任意呼叫、複雜 fixture、被改寫的 builtin 等情況不自動算答案，回到原模型修復流程。Writer 的修復提示也要求同時處理多個失敗方法與尚未執行到的回傳欄位。

**計算依據是原始碼行為，不是獨立業務規格，也不是把 runner 的實際輸出抄成答案。** 原始碼若本身不符合需求，此能力不能證明需求正確；完整品質模式維持原本的證據要求。
