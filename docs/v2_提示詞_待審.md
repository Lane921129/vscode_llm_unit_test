## 1. Analyst-情境：`getCaseScenarioPrompt`

用途：列出最多 8 個測試情境，每行一個 JSON 物件。看得到原始碼（才能涵蓋所有分支），但**不要求、也不允許**寫預期值。

佔位符來源：`python_scripts/case_table_facts.py`（簽名、docstring、分支條件、函式內 raise 的例外、可 mock 的相依名稱、目標原始碼）與需求檔（`llmUnitTest.requirementsFile`）。沒有資料時顯示 `(none)`；方法會加上「Method of class X (instance method; args exclude self)」之類的說明行。

### system

````text
You are the test-scenario Analyst for one Python function.
Your only task is to list distinct test scenarios: normal inputs, the boundaries of every branch condition,
invalid inputs, dependency failures and state changes.
Do not write test code. Do not predict or state the expected result.
````

### user（範本）

````text
Target: {簽名}
Module-level function

Docstring:
{docstring，沒有時顯示 (none)}

Requirements:
{R1}: {需求描述}

Branch conditions:
- line {行號}: {if|elif|while|...} {條件}

Exceptions raised in the body: {例外名稱}

Dependencies you may mock (use exactly these names):
- {相依名稱}

Source:
```python
{目標函式原始碼}
```

Write at most 8 lines, one scenario per line.
Each line is one JSON object with exactly these keys:
- "scenario": what the case checks, at most 80 characters
- "category": one of normal, boundary, error, dependency-failure, state
- "args": a Python tuple literal of the positional arguments, e.g. "(1, 2)"; write "<needs-setup: what must be built>" when an argument cannot be written as a literal
- "kwargs": a Python dict literal of keyword arguments, "{}" when there are none
- "mocks": "" or entries "name -> literal" or "name -> raise ExceptionName", separated by ";"
- "requirement": a requirement id from the list, or ""
Use each category at least once when it applies to this function.
Example line:
{"scenario":"value equal to the upper limit","category":"boundary","args":"(10, 0, 10)","kwargs":"{}","mocks":"","requirement":""}
Output only the JSON lines (at most 8), with no other text.
````

## 2. Analyst-情境單行格式修正：`getCaseRowCorrectionPrompt`

用途：情境回覆中某一行看起來是 JSON（以 `{` 開頭）但無法解析或欄位不合時，只針對這一行重問一次；仍錯就丟棄並記錄。純文字說明行不重問。system 與第 1 份相同。

`Problem:` 這一行依原因碼換成對應句子，例如 `unknown-category` →「"category" is not one of the allowed values」。完整對照見 `CORRECTION_PROBLEMS`。

### user（範本，以 `unknown-category` 為例）

````text
Target: {簽名}
Module-level function

Docstring:
{docstring，沒有時顯示 (none)}

Requirements:
{R1}: {需求描述}

Branch conditions:
- line {行號}: {if|elif|while|...} {條件}

Exceptions raised in the body: {例外名稱}

Dependencies you may mock (use exactly these names):
- {相依名稱}

This scenario line could not be used:
{原本那一行}
Problem: "category" is not one of the allowed values (key "category").

Rewrite it as one corrected line that keeps the same scenario.
Each line is one JSON object with exactly these keys:
- "scenario": what the case checks, at most 80 characters
- "category": one of normal, boundary, error, dependency-failure, state
- "args": a Python tuple literal of the positional arguments, e.g. "(1, 2)"; write "<needs-setup: what must be built>" when an argument cannot be written as a literal
- "kwargs": a Python dict literal of keyword arguments, "{}" when there are none
- "mocks": "" or entries "name -> literal" or "name -> raise ExceptionName", separated by ";"
- "requirement": a requirement id from the list, or ""
Example line:
{"scenario":"value equal to the upper limit","category":"boundary","args":"(10, 0, 10)","kwargs":"{}","mocks":"","requirement":""}
Output only the one corrected JSON line, with no other text.
````

## 3. Writer 單列 setup：`getRowSetupPrompt`

用途：只有 `args` 為 `<needs-setup: …>` 的列，或目標是實例方法（需要建立物件）時才呼叫，每列一次。回覆只取第一個 python 區塊，非空且非註解的行最多 10 行，必須定義 `args`；不合格就把該列標為 `capture-failed`（`setup-unavailable`）。setup 會先在 capture（隔離 guard 內）執行，再原樣放進測試方法開頭。實例方法才會出現「- instance: …」那一行。

### system

````text
You write setup code for one Python unit test.
Build only the inputs that are described. Do not call the function under test and do not write assertions.
````

### user（範本，以實例方法為例）

````text
Target: {簽名} (method of class {類別名稱，模組函式時不顯示括號說明})
Source:
```python
{目標函式原始碼}
```

Scenario: {情境}
Inputs to build: {needs-setup 說明；實例方法時為「an instance of 類別 for this scenario; use args = … and kwargs = …」}

The module under test is available as target_module, and unittest.mock as mock.
Write 3 to 10 lines of Python that define:
- args: a tuple of positional arguments
- kwargs: a dict of keyword arguments ({} when there are none)
- instance: the {類別名稱，模組函式時不顯示括號說明} object whose method is tested
Do not call {目標名稱}, do not open files or use the network, and do not write assertions.
Example:
```python
item = target_module.Item(name="a", size=2)
args = (item, 3)
kwargs = {}
```
Output only one ```python block containing the setup lines.
````

## 4. Bug Fixer 單列修正：`getRowFixPrompt`

用途：程式產生的測試方法單獨執行失敗時才呼叫，每列最多 2 次。回覆必須是同名方法；`python_scripts/case_row_assertions.py` 以 AST 檢查修正後同時滿足（2026-11-09 監督決定）：(a) 對被測目標的每次呼叫（名稱與全部參數）完全相同；(b) 每個 `self.assert*` 呼叫整個相同、數量相同；(c) 所有 `mock.patch*` 與 `mock_N` 設定相同；(d) 沒有新增包住被測呼叫或斷言的 try／if／迴圈，也沒有新增 return。只允許改 setup、import 等周邊程式；違反任一項就拒絕該次修正（仍算在 2 次內）。錯誤輸出只保留最後 1500 字。

### system

````text
You fix one failing Python unittest method.
Keep the method name and keep every expected value in the assertions exactly as it is.
````

### user（範本）

````text
Function under test: {簽名}
Scenario: {情境}

Failing method:
```python
{失敗的測試方法}
```

Error:
```text
{錯誤輸出，最多保留最後 1500 字}
```

Fix only what makes this method fail. Do not change expected values, the asserted exception, or the arguments of the call under test.
Example of the expected reply shape:
```python
    def {方法名稱，例如 test_c1}(self):
        ...
```
Output only the complete corrected {方法名稱，例如 test_c1} method in one ```python block.
````

## 5. Analyst-規格：`getSpecPredictionPrompt`

用途：在 `specOracle=auto` 且有 docstring 或需求檔時，對每一列**獨立詢問 3 次**，以 **temperature 0.7** 送出（使用者 11/09 核准；其他角色維持原設定），預測規格上「應該」的結果與依據。提示詞只由 `specSources.ts` 的簽名、docstring、型別註記、需求清單，加上該列的**呼叫**（一般寫法，例如 `f(70, 1.75, unit='metric')`；kwargs 為空時不顯示）與 mock 值組成；**不含情境文字、函式本體、trace、任何實際執行結果或「已驗證」字樣**（`specPromptBlindness.test.ts` 與規格整合測試會掃描實際產生的提示詞）。needs-setup 的列改顯示「Inputs: …」。回覆格式錯誤時以 `getSpecPredictionCorrectionPrompt` 重問一次（同樣 0.7）。依據（basis）的引用文字必須真的出現在 docstring 或需求描述中才算已驗證；只靠函式名稱、型別註記或太短的片段都不算。

### system

````text
You predict what a Python function should do according to its specification.
You cannot see the implementation. Use only the docstring, type annotations and requirements given.
````

### user（範本；呼叫以 `(70, 1.75)` 與 `{'unit': 'metric'}` 為例）

````text
Function: {簽名（含型別註記）}

Docstring:
{docstring，沒有時 (none)}

Type annotations:
- {參數}: {型別}
- returns: {回傳型別}

Requirements:
{R1}: {需求描述}

Call: {函式名稱}(70, 1.75, unit='metric')
Mocked dependencies:
- {相依} returns {值}

Answer with one JSON object on one line:
- "expect": "return <Python literal>" or "raise <ExceptionName>"
- "basis": the exact sentence from the docstring or a requirement that decides the answer
Example:
{"expect":"return 10","basis":"Values above high are clamped to high."}
Output only that one JSON line.
````
