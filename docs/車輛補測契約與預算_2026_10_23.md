# 車輛補測 Writer：契約、輸出額度與真實模型驗證

範圍仍是完整車輛專案。本次修補先針對第一個阻擋目標 `main.py::get_plate_no_from_event`；單一目標有進展不代表整批完成。未修改應用來源、批准資源或既有結果。

## 原問題與修改

前次實測 `writer-live-20261023-rPJeky` 的 seed 已通過實跑與 Reviewer，並完成 builtin 突變；物件補測工具也已取得觀測。然而第二輪 Writer 仍繼承完整 suite 指令，再以後附文字覆寫成一個新增方法。估算輸入7446 tokens，Context8192增至11264；普通非 seed Writer 沒有明傳 `num_predict`，最後在等待 HTTP 標頭時達300秒期限。

本次讓補測使用獨立契約，只請求目前缺口的一個新方法；保留完整來源、必要 setup、觀測、原執行基線與修訂草稿，減少重複固定說明。宿主持有執行基線時才標記 `single-test-addition`；Local Writer／其修訂以1536作初始輸出預留，實際 wire cap與輸入預算成對。生成前估量、各容量反算、增容和最終發送使用相同 scope；既有 learned floor、唯一恢復、原期限／計數與品質 gate 不變。

## 下一個已證實的缺口

第一輪工具觀測要求 `e.data` 的 getter 拋出 `Exception`，目標自行捕捉後返回None。第二輪 Writer實際寫成 `data=None`，雖然同樣返回None且實跑通過，卻沒有走原計畫的例外分支；259、260、266、267、268仍未覆蓋。工具第二輪提供缺少data屬性的不同配方，第三輪又重複既有測試，未形成可採用的新情境。

因此目前主要問題是**參數物件觀測至新增測試的重放契約仍不足**。下一步應將本輪配方、屬性讀取例外／缺少／常數值明確區分，對可靜態證明偏離的新增候選提供精確 Writer 修訂；未知自訂 fixture 不可假裝已匹配，也不能為增加通過率取消同候選實跑、Reviewer、覆蓋或突變門檻。之後需再次實測此目標，再擴至完整車輛批次；目前沒有整批成功證據。
