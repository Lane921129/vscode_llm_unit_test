# 結果與失敗報告

重新編譯、重啟擴充功能後，新執行會採用以下格式。歷史結果不覆寫。

| 檔案 | 用途 |
| --- | --- |
| `batch_summary.md` | 本次已開始測試目標的模型、結果／失敗原因、覆蓋率及突變分數；連到測資與突變案例 |
| 函式目錄的 `final_report.md` | 所選函式最後保留的測資、其目標行覆蓋率及突變前／後和結果 |
| 函式目錄的 `failure_report.md` | 首次／最近失敗、最終原因、完整依序事件、各輪分析、修復及降級；曾失敗後成功也保留並註明 |
| 批次根目錄的 `failure_report.md` | 掃描／環境／取消／缺報告等問題，以及逐目標完整流程連結 |
| `workflow_report.md`／`batch_workflow.md` | 完整執行與稽核明細；成功、略過也可追溯 |

最終結果不再包含未選函式、其他專案或相依原始碼、分析師全文、模型原始回覆與反覆生成的候選。Dummy、尚未實際執行的 Stub、無函式檔案及未開始目標不列入結果表；完整批次清單仍會記錄它們，因此略過與取消不能變成全部通過。

測資只呈現保存且雜湊吻合的保留版本，不選最新檔案或歷史最高分。覆蓋率使用所選目標實測行數；突變列出同一來源／目標／測資的變異案例。未量測、來源變更、候選身分不符時顯示 N/A；100% 不代表 Reviewer 已完成。僅執行模式明示覆蓋／突變未執行。

排查時從 `failure_report.md` 開始，再依其連結讀取 `role_events.jsonl`、`run_manifest.json`、`function_knowledge.json` 與保存的基線。完整模型回覆不會被新報告或角色事件保存；拒絕仍記錄原因、回覆 hash／長度與角色診斷。scorecard 使用 `run_manifest.report` 辨識新格式並核對原有品質證據；舊格式仍支援。
