# BMI 三批補測失敗：根因與驗證界線

分析範圍為 `bmi_2026_10_26_22_21`、`bmi_2026_10_26_22_38`、`bmi_2026_10_26_22_45`。結果位於實驗室 `test/result`，本文件只記錄必要統計與事件定位，不複製完整模型回覆或私有來源。三批來源 SHA-256 均為 `5aca791295fd2bbba3dac8f5e8a4dafe65c1b5075fbed0dcb586cac67bb5d9d7`，與目前 BMI 診斷 fixture 一致。

## 為何只剩一個弱測試

首問的一個方法、一個呼叫，是 host 的 `one-complete-observation` 任務切分設計。它先以 `(1, 1)` 的已觀測輸入建立可執行 seed，期望後續根據行覆蓋與存活突變補測。因此，一個 seed 不能證明模型只能寫一個測試，也不能當成完整交付；補測流程失敗後保留 seed，才造成最終成果很弱。

| 批次／模型 | 已達到的階段 | 實際阻擋 | 保留成果界線 |
| --- | --- | --- | --- |
| 22:21／codellama:34b | 約 869.5 秒；格式修訂後 seed 真實執行通過 | tuple 的 `assertAlmostEqual` 觀測狀態 unknown；Reviewer 要求斷言依據；後續 Writer 擴成 5、6 方法，被局部修訂範圍拒絕 | 70% 行覆蓋 seed；無 Reviewer 批准、無突變量測 |
| 22:38／codellama:13b-code | 約 288.5 秒；Analyst 完成 | 兩次 Writer 都生成 4096 tokens 並以 length 結束；格式恢復有啟動但仍無完整候選 | 無可執行候選；未到 native、Reviewer 或突變 |
| 22:45／codellama:13b | 約 217.2 秒；有效 seed、兩個斷言 verified、Reviewer 批准；真實 Mutatest 24／39 | 三案補測停在第一案，三次 `invalid-python-structure`；後續修訂也首行 SyntaxError | seed 行 7／10、突變 61.53846%，仍未滿足完整品質 |

三批載入同一 build（2026-10-26T14:16:46.007Z，bundle SHA-256 `62343d7a5e893f233702d903b439b55f184ebbdff9e022ca0b765717b373440b`）；HTTP 皆 200，輸入未超過設定 Context，結束時仍有大量時間。不能再把這三批歸因於舊 build、網路逾時或 BMI 算術本身太難。不同模型仍有不同的輸出合約失敗，不能承諾一個修正同時解決三者。

## 22:45：已有證據，卻卡在包裝到 AST 的交接

`loop/_run/role_events.jsonl` 的 seq 67 批准 seed，seq 72 量測 Mutatest（`mutatest-ast-3.1.0-v2`，約 12.315 秒）。存活 15 個，未覆蓋來源行 15、17、19；61.5% 是本次突變集合比例，不是需求完成比例。

系統已規劃並真實觀測 18.5 邊界輸入族，包含 `(0.001849, 1)` 回傳 `(18.49, "體重過輕")` 及 `(0.00185, 1)` 回傳 `(18.5, "健康體位")`。缺的不是計算工具或這兩案 expected。保留 seed 的 height=1 會讓 planner 產生不具代表性的極小 weight；這是通用輸入規劃的後續改善方向，不能硬編 BMI 特殊規則。

seq 124／142／160 都拒絕第 1／3 案，後兩案未執行。seq 163 的完成回覆形狀為 686 字元、13 行、兩個 fence marker、一個方法、兩個斷言、零重複行，抽取後報 `SyntaxError 1:1`。seq 183 的普通修訂為 1583 字元、45 行、兩個 fence marker，同樣 `1:1`。這與 Markdown 包裝仍在解析輸入內高度相符；隱私產物沒有完整原文，不能證明這幾份 fence 內的 Python 必然有效。`loop/2/loop2_test.py` 是恢復的 seed，不能當成被拒回覆閱讀。

最小重現使用中性 `target` 及同一份有效 TestCase，實際呼叫 TypeScript 抽取器與 Python AST 合併工具：

| 完整模型回覆形狀 | 舊初始檔案抽取 | 舊補測抽取／合併 |
| --- | --- | --- |
| 唯一 Python fence | 抽出程式碼 | 合併成功 |

`testMerger.ts` 原本只有整份錨定的 regex，與初始 `extractPythonTestCode` 的詞法掃描不同。這是可確定重現的 host 缺陷；對歷史回覆的判斷仍保留上述限制。繼續加強「只輸出 Python」提示或重送整份修訂，都無法修正這個抽取落差。

## 22:21 與 22:38 的不同根因

34B 對整個 tuple 使用 `assertAlmostEqual`。標準 unittest 在兩側完全相等時可提前返回，因此本次是真執行通過；兩側不等時則可能因 tuple 相減而 TypeError。`review_test_facts.py` 對該 assertion 的近似比較僅核實 int／float，所以狀態保持 unknown。既有回傳觀測仍存在，unknown 表示工具未核實這種比較，不表示 expected 已證明錯誤。Reviewer 要求 exact-input 或明確合約依據，不能直接套用前次「否定合法 float／str」的機械矛盾修正。後續 Writer 應局部修正比較方式及依據，卻擴寫整套測試，才觸發已有範圍保護；本次不放寬該保護。

13B-code 第一次 length 樣本有 103 非空行、87 重複行、14 fence marker、7 方法簽名、0 斷言。第二次已切換 raw seed completion，沒有 fence 或 test 方法簽名，仍 length。恢復確實執行且輸出形狀有改變；不能說第二次只是相同外框重複，也不能以再加輸出 cap 保證能完成。

## 本次修正與驗收

補測委派給既有 Python 抽取器，新增 addition 模式以辨識裸 test 方法。只移除唯一完整 fence 的傳輸包裝；多 fence、未閉合尾段、無 fence 的說明保留供拒絕，多行字串原值不變。這不產生輸入、expected 或測試 body。AST 基線保護、完整觀測族、native、同候選 Reviewer、指定引擎與品質門檻保持。

回歸涵蓋中性裸方法及完整檔案的前後說明、JSON code 包裝、多候選與未閉合拒絕、literal marker／縮排、真 Python 錯誤及已通過方法改寫拒絕。正式 BMI 固定回覆整合讓補測帶前後說明，檢查完整三案合成、seed 保留、重新執行及審查後才突變。結果記於本次 `CHANGELOG.zh-TW.md`。

上述整合使用固定角色回覆與真正 Python／突變工具，不能宣稱 codellama:13b、13b-code 或 34b 的新實測已通過。實驗室重測需載入新 build、維持來源／full／Mutatest／Context8192 及原時間設定，核對新增方法、完整輸入族、同測試 hash 的審查與量測；只保留 seed 仍是未完成，不能以 70% 行覆蓋當成功。
