## 本次新增修復

### 單次時間觀測不能當成固定斷言

舊結果把一次 Trace 的當下時間寫成固定相等斷言，兩分鐘後基線自然失敗。用當時最新版 `144adfa` 與中性 `datetime.now().isoformat()` fixture 重現：Trace 被接受、結構檢查通過、獨立 unittest 卻失敗。換模型、增加 timeout 或提供更多檢索語境都無法修復這個 runner 產生的錯誤 oracle。

本次以實際 callable 身分追蹤標準庫時鐘、隨機／熵及程序身分讀取，保留觀測但標記不可作為固定回傳或例外事實。涵蓋 alias、helper、constructor、property、async、generator、新建 worker thread，以及應用模組初始化呼叫 UUID／隨機 helper 的情況。既有 Tier 1、例外及 Trace 斷言驗證遵守同一旗標，不再產生這類固定值基線。

同一測試若明確控制時間使用點，仍可根據 mock 的輸入與回傳驗證行為。每次呼叫內建立且明確 seed 的私有 RNG 可保留；共享 RNG 不因曾設定 seed 就視為可重播。Writer／Reviewer／Bug Fixer 都收到證據限制，沒有模型或 provider 名稱特例。

此觀測器不是一般純度或決定性的完整證明。標準庫 `time.localtime/gmtime/ctime/asctime` 等可省略時間參數的 C 呼叫採保守診斷；不能追蹤的原生 extension 內部讀取不在本次涵蓋範圍。匯入初始化讀取 ambient state 會保守影響該模組的觀測。獨立基線、隔離執行與所有品質 gate 繼續保留。

### 整批進度與環境摘要

新增每批 `batch_manifest.json` 與 `batch_summary.md`，記錄建置、模型、Python、角色契約、已發現來源與 qualified target、逐項狀態及模型請求數。新批次使用獨立輸出根目錄，同分鐘建立 `__run2`；取消後立即重跑不共用紀錄。

掃描失敗不再默默變成零函式。若語法錯誤使目標數未知，保留 discovery failure，批次不能是 complete；缺報告、缺 checkpoint、仍在執行或 provenance 不一致也明示未完成。`complete=true` 只表示清單已處理完，`allTargetsPassed=true` 才表示所有目標完整通過。Dummy／Stub、未完成審查與品質不足均不算 passed。

環境摘要按缺模組與「被阻擋操作＋專案相對位置」歸組。摘要不保存 provider 回覆、來源原文或憑證，也不另請模型分析環境問題。保留匯入副作用防護；沒有自動安裝原應用相依或改寫其初始化邏輯。

## 驗證與限制

新增回歸驗證實際 Python Trace 的時間／熵旗標、合法 mock、純 async、seeded RNG、匯入初始化、worker thread 及 profiling hook 還原；Node 測試串接 Trace、Tier 1、例外證據與提示詞。

正式批次 command 的中性整合測試涵蓋缺相依、共同匯入副作用、語法錯誤、取消、重跑、輸出資料夾排除及證據缺失。另以固定 provider 測試回覆產生時間 mock，實際經 Python、coverage、Reviewer 契約與 basic mutation：完整通過，mutation 100%，無不穩定 Trace 基線。固定 provider 回覆不是雲端或本機模型實測。
