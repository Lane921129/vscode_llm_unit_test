# CI 修復結報（2026-10-04）

本文件保留 2026-10-04 的歷史驗證快照，於 2026-10-22 補納版本控制；文中「未提交」為當日狀態，不代表目前交付狀態，也不能當成現行版本 CI 已通過的證據。

## 問題與修正

CI 的 Ubuntu／Windows、Python 3.12／3.13 四格矩陣共用回歸測試；共同測試失敗足以使四格全紅，不能據此認定各平台都無法執行。

- Node 測試檔改為順序執行；每個整合測試仍可使用受控 Python 突變 worker，避免主機核心數將子程序數量倍增而導致假性逾時。
- Trace 整合測試的子程序限制由 10 秒調整為 30 秒。
- Orchestrator 回歸測試對預設突變預算的期待同步為目前產品的 60 秒；明確指定預算的驗證繼續保留。
- 驗證第二輪改善的角色整合測試明確使用嚴格品質策略，並只計算已量測的突變事件，避免預設 80% 門檻提前結束或將進度事件誤算為結果。
- 角色整合測資加入排序大於 `plain` 的字串，能識別 `==` 改為 `>=` 的比較突變，補足第二輪測試的實際辨識能力。
- 展示測試改為核對當次突變紀錄與實際報告，不再寫死舊引擎的突變數量。
- 輸入規劃器優先保留每個數值運算輸入為零的候選，防止有界案例清單提前耗盡而遺漏除零例外。候選仍由隔離執行取得結果，規劃器不宣告預測結果。
- 固定 tuple 增加單一元素變化，避免算術與索引突變碰巧得到相同輸出。
- 縮減重複的通用數值候選，保留零值與來源條件案例，避免 Writer 的證據提示超出預算。
- 候選去重時保留來源條件的證據分類，修復基準輸入與字面值邊界重合時被錯誤篩掉的問題；未標註型別的 echo 測試明確提供輸入。
- typed constructor 公開測資使用兩個不同元素，能區分首元素與尾元素索引。
- 分支回歸測試要求所有非例外訊息突變被殺死；例外訊息的兩個突變仍記為存活，因該測試只驗證例外類型。正式品質門檻沒有降低。
- Tier 1 回歸測試統一選用專案 `.venv` 的 Python。
- CI 拆開 Node、Webview、Python 與編譯步驟；前一階段失敗後仍收集其他階段結果，各失敗仍使工作失敗。
- Python 回歸清單加入型別／輸入規劃、突變 v2、突變程式碼與外部引擎測試。
- 固定直接宣告的 coverage、mutmut 與 mutatest 版本；保留 Python／平台條件，避免工具版本漂移。
- 清除先前留下的 `test/ci-head-370b7e5-20261001` 暫存目錄，先移除環境與依賴 junction，保留其原始目標。

## 驗證

本機驗證環境為 Windows、Python 3.13.2、Node 24.14.1。CI 配置使用 Node 22；Ubuntu 與 Python 3.12 須以 GitHub Actions 的實際執行結果確認。

- Python 完整回歸：342 個案例，335 通過、7 略過、0 失敗（373.585 秒）。略過項目為 6 個需要舊版 mutatest AST API 的測試，以及 1 個目前使用者無符號連結權限的測試。
- Node 完整回歸首輪：506 個案例，500 通過、4 失敗、2 略過。修正後重跑原先失敗的改善流程、展示、角色整合與 Tier 1 corpus，均通過；Tier 1 邊界與數值整合也通過。沒有宣稱最後再次完整重跑全部 506 個案例。
- 角色整合最終重跑：1 個通過，涵蓋第二輪改善、Reviewer 受阻、中斷保留、來源改動、外部引擎與部分改善等情境（212.565 秒）。
- Webview 檢查、TypeScript 型別檢查、lint 與擴充套件建置通過。
- `pip check`、工作目錄／Git 歷史機密掃描與 `git diff --check` 通過。

## 交付狀態與限制

修復保留在本機工作目錄，包含原先未完成的型別形狀／輸入規劃功能；未修改外部被測專題，尚未提交或推送這批變更。

CI 四格矩陣需推送後確認。順序執行降低並行資源競爭，也可能增加總耗時；目前優先確保正確執行與完整診斷，CI 上限設為 45 分鐘。略過測試不視為通過。
