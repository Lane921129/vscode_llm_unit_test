# 品質回滾與角色契約修復

本次依 cleaner 八項結果改善正式管線。原始結果中，環境預檢八項全部通過，但完整驗收沒有通過項目；其中一項在未覆蓋行由 15 減為 2、突變分數由 33 升為 61 後，被品質缺口文字比較誤判為退步。本文不保存私有來源或模型完整回覆。

## 改動

1. 以結構化未覆蓋行、未覆蓋分支集合比較品質；部分改善可以保留。新增缺口、覆蓋證據消失、突變分數下降、舊突變體重新存活仍受保護。停滯判斷採相同缺口身份。rollback 事件新增比較診斷，測試、coverage、mutation 與 review status 維持同候選同步。
2. Reviewer 改用 `review-v6`，引用標示於 TEST_FILE 的 `L1` 等行號，由本地取得精確測試原文，減少模型重新打字造成的錯引。禁止來源行號、未知／空白／註解行與混用新舊欄位。明確 target binding 矛盾、要求修改目標實作或 mock 目標自身的回覆保持未完成，不交 Writer 執行，也不刪除 finding 後當作通過。
3. 品質分析改用 `quality-task-v2`，每輪選一個真實量測的缺口或存活突變體，最多要求一項小任務。證據由 ID 綁定，不讓模型重打或發明量測。格式補正最多一次，與原請求共用絕對 deadline；傳輸錯誤與取消不觸發格式補正。純 Python 資格模型仍採文字傳輸，其他模型可使用 schema，所有模式接受相同的本地 parser。

模型資格契約升為 `python-unittest-v4`，舊結果保持過期而不升級。需要在側邊欄重新執行模型測試，確認 Writer、Reviewer、Bug Fixer 各自的資格。

生成測試的 Python binding gate 另攔截可解析的標準 patch 對所選目標／類別的替換，並將無 decorator 的 unittest 方法額外必填參數判為結構問題，交 Writer 而非 Bug Fixer。標準 dependency patch 與 decorator 注入 mock 的既有行為保留；未知動態 binding 仍依執行與品質 gate 判讀。

## 驗證

回歸包含 15→2 行部分改善、行與分支倒退、證據變未知、停滯計數、行號解析、矛盾審查保持未完成、真實 blocking 保留，以及格式補正／取消／deadline。端到端使用固定模型回覆與中性 static method，實際執行 Python unittest、coverage 和內建 mutation，驗證第二輪只改善部分品質時仍保留較高分成果；另驗證矛盾審查不觸發 Writer 重寫。

完整測試與提交快照驗證數字記於同日 `CHANGELOG.zh-TW.md`。未將先前暫停中的 Python 環境功能混入這次提交。

## 實驗室重測

1. pull 後重新建置，再啟動 F5 的 Extension Development Host。
2. 在側邊欄重新測試目前模型，更新三種角色資格。明確手動 Tier 仍保留既有行為，但不能當成角色資格已通過。
3. 使用相同的 cleaner 來源、Python 環境與模型重新測試；沿用 20 秒突變與 5 輪預設，不放寬任何 gate。
4. 檢查 manifest 的 `roleContracts.reviewer=review-v6`、`qualityAnalyst=quality-task-v2`。對照各輪 `coverage`、`mutation`、`baseline` 事件：缺口縮小不應被判定 `lostQuality=true`；真正退步應附比較理由。
5. 對照 Reviewer 的行號引用／矛盾診斷、品質分析任務有效率、模型請求數與最終保留分數。只採同一候選的品質與審查狀態，不把不同輪最高分拼成通過。

## 限制

Reviewer 的自然語言矛盾檢查只涵蓋明確語句，不能證明任意評語正確；未辨識的錯誤意見仍可能發生。行號有效也不代表理由正確。格式有效的品質任務仍是模型假設，不是 assertion oracle。真正生成的非法 self-mock／呼叫／斷言還須接受原本結構、Trace 與執行品質 gate。

沒有在本機重跑原應用、CodeLlama 13B 或 1B～5B 真實模型；中性 fixture 通過不能當成實驗室八項已通過。RAG 可補充來源語境，不能取代本次確定性流程修正或執行證據。
