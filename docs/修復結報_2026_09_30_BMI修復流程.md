# BMI 錯誤預期值與無效修復：修復結報

## 問題與修正後行為

2026-09-29 23:38 的 BMI 測試把 `calculate_bmi(50, 160)` 預期寫成 `(18.5, "體重過輕")`。Writer 移除錯誤的目標 Mock 後，Bug Fixer 回傳的方法未改變；共用的兩次修訂額度用完，流程停止。

本次修正工具的提示、無變更後接手流程及資格驗證。原 BMI 與原歷史結果沒有修改；工具內沒有寫死 BMI 公式、數值或分類。

## 修復項目

### 1. 統一預期值的證據規則

- Writer 與 Bug Fixer 都可使用來源支持的簡單確定性計算關係，核對輸入、單位、計算、四捨五入與各回傳欄位。
- 純計算若沒有已識別的外部操作，不要求建立 Mock；仍須真實呼叫目標。
- 不得僅複製實際回傳值當答案，不得用目標自身計算預期值，不得弱化斷言、跳過測試或替換目標。
- Bug Fixer 契約更新為 `bug-fix-v5`。

### 2. 無有效變更時，給 Writer 一次接手機會

觸發條件限定為 Bug Fixer 回傳已嘗試候選，或 Python AST 判定 `no-method-change`。

流程保留原測試及原始執行錯誤，把完整測試與來源證據交給 Writer。一般修訂上限仍為兩次；若已用完，最多保留一個額外 Writer 接手槽位。每個候選流程至多接手一次，仍計入原本的目標總請求、候選、token 與時間預算，並遵守取消。

Writer 接手仍無進展、違反結構規則、執行失敗、使既有案例退步或仍有 blocking 審查時，該流程停止；不在接手後重新展開無限修復。

import 衝突、工具錯誤及其他越界修改不會藉此取得額外接手額度。接手後候選仍須經原本的結構、binding、隔離執行與適用的審查流程。

### 3. 修正既有通過案例的比對

執行驗證每次產生不同檔名，例如 `exec1_test.py`、`exec2_test.py`。舊比較將檔名算入案例身分，可能把仍存在的通過案例誤認成消失。

現在只移除 runner 已知的當次候選模組前綴，保留類別與方法名稱。保留案例不再被不同檔名誤擋；刪除、改成失敗、改成跳過或改到其他類別仍不算保留。

### 4. Bug Fixer 資格必須證明有效修復

舊資格探測主要驗證方法片段能否合併。新探測提供實際錯誤案例 `increment(1)` 預期為 3，要求保留輸入與直接斷言、修正成 2，同時保留另一個通過案例。

固定案例的修改與格式確認後，必須使用使用者選定的 Python 通過隔離執行，才標示 verified。未修改、改輸入、常數對常數、以目標自行計算答案、跳過或越界修改都無法取得資格。探測採限定的固定語句格式，不宣稱涵蓋任意等價 Python 寫法或一般專題的完整修復能力。

本機、雲端與自訂 API 三條連線探測路徑均使用選定的 Python。資格版本更新為 `python-unittest-v6`，舊結果需要重新探測。
