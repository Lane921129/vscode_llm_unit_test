# 18:29 批次修復與雲端實測

## 根因及處理

18:29 原批次的失敗證據包含：多方法失敗誤交單方法 Bug Fixer、Writer 重複候選遺失最新原因、Reviewer schema／parser 數量契約不同、缺漏情境被當成 blocking，以及巢狀來源相依解析失敗。原批次未改寫，也未以本機回歸替代其成績。

本次修復統一 `review-v5`、先執行再審查、唯一失敗方法分流、完整 Tier 3 輸出及載入來源解析；新增回歸涵蓋上述分支及拒絕反例。實測又重現 Reviewer 將比較式當佔位符，已修正並補測。所有生成產物仍通過原本的結構、Trace 證據、隔離執行、coverage、mutation 與完成審查要求。

async 實測另發現系統 Trace 基線本身使用 `__import__('asyncio')`，被合併後的安全 gate 擋住；Writer 無法消除每次被系統還原的基線。已改為一般標準庫 import，補真實 Trace → 合併 → 結構與 binding 驗證 → unittest 執行的 coroutine／generator／async generator 回歸。系統基線在獨立執行前先驗證結構與安全，失敗停止模型修訂。已知重複失敗的診斷批次在重載時停止，原 `running` 紀錄保留為未完成證據。

完整五類實測又發現 HTTP fixture 的 `UnsupportedProtocol` 已存在於實際 Trace，但例外事實解析只認部分名稱結尾，導致基線被拒絕。修正為確切 Python identifier path／`exception_qualname`，仍拒絕副作用阻擋觀測及診斷句子，補中性自訂例外的真實 Trace、基線與 unittest 回歸；沒有放寬安全 gate。
