# Source-bound Writer method edits

This increment handles formal Reviewer findings that do not request a missing scenario and whose cited lines identify existing unittest methods. The Writer returns only those methods, inside their existing class-name wrappers in one Python fence. Complete suite replies, module imports, fixtures, unrelated methods and method renames are rejected. A necessary import can be local to a selected method.

`WRITER_METHOD_EDIT_V1` supplies the original candidate `baselineHash`, a `planHash` and exact `methodIds`. The complete read-only candidate, source context and original structured review findings remain in the prompt. No source, finding or basis is clipped to make this request fit. Existing final request capacity checks decide whether it can be sent.

## Composition contract

`edit_test_methods.py` parses text without importing or executing submitted code. Its plan binds the exact UTF-8 baseline and cited lines to direct `test_` methods in known unittest TestCase classes. It supports multiple classes, same method names in different classes, async methods, existing decorators and CRLF. Ambiguous definitions, class/fixture/module lines and unsupported layouts return explicit reasons and grant no whole-file editing permission.

The response must supply every planned method exactly once. Signatures, annotations, decorators and async status must remain AST-equivalent. Class wrappers only identify the existing owner; they cannot change its base, decorators or fixtures. Multiple owners require explicit class wrappers. Replacements may be formatted within their selected spans; literal values remain AST values. Every byte outside those original spans, including other methods and fixtures, stays unchanged.

Apply reconstructs the plan from the original baseline and checks both hashes. It rejects no-op edits, missing/duplicate methods, scope expansion and signature changes. Python compares the resulting AST with the original after excluding only the selected method bodies. Node separately checks the returned offsets against its original plan, rebuilds the UTF-8 byte edits and verifies the complete output hash and bytes. Neither operation creates inputs, expected values or assertions.

Both baseline and replacement have a 1 MiB UTF-8 limit, parsed trees have a 20,000-node limit and a plan can select at most 32 methods. Tool transport, invalid DTOs and timeouts stop as tool failures. A malformed model replacement remains a rejected model edit; it does not authorize native execution or silently become a partial success.

## Formal workflow

The host caches the exact original plan and complete review packet for bounded correction. A rejected edit uses the existing revision budget and deadline. It cannot extend the deadline, add requests or fall back to rewriting the entire baseline. A changed or unavailable tool result does not trigger model repair of the tool.

`OUTPUT_CLASS_HEADERS_V1` lists the exact original owner headers from the AST method IDs, without placeholder class names. This is host-owned scope packaging, not generated test bodies, fixture values or assertions. Source-supported case inputs and verified assertions stay protected; a copied initializer in a rejected draft is not itself proof of required setup.

The composed candidate still passes existing preservation, structure, source-bound observations, native target execution, fresh same-candidate Reviewer approval and coverage/mutation gates. When editing an unapproved quality addition, the original approved seed stays protected and the existing exact focus-input and parameter-fixture replay checks run again on the entire composition. An `applied` event records AST composition; it is not execution, review or quality approval.

The fixed Writer qualification probe still certifies only its public sample. It does not establish a model's method-edit capability; formal edits must pass the actual contract and gates.

## Remaining scope

Pure `missing-scenario` reviews now use addition-only composition against the exact executed candidate under review, including any quality additions it already contains. The host caches that complete review packet by candidate hash across rejected fragments. The response contract contains no full-file rewrite instruction; at least one new method is required. Existing methods and fixtures remain with the host. Ambiguous bare methods across multiple TestCase classes require an explicit existing class header, rather than an inferred owner. Merge tool failure stops; model scope rejection uses only the remaining original revision budget. The complete composition still needs native execution and fresh same-candidate approval.

Checker `writer-undefined-name` findings now also use this contract in both `execution` and the `full` seed correction. The current Checker DTO's class, method and AST line select the owner; method-name regexes and failure prose cannot select a span. The exact rejected candidate is the read-only baseline. The full seed uses its original one correction slot, keeps the selected case evidence and revalidates the entire composition. Execution retains the narrower source-proven helper-import selection before requesting a method replacement when that selection is inapplicable.

Binding edits have their own output scope, so request packaging cannot turn them back into complete seeds or new additions. A scope rejection, no-op, unresolvable location or exhausted correction stops with a typed validation failure; it cannot reopen a whole-file Writer or Tier fallback. Successful composition still grants no execution or quality approval. Fixed-response integration exercises both modes' success, out-of-scope and unchanged responses; the full success fixture runs native execution, fresh same-candidate review and builtin mutation.

An unused dependency-result assignment has the typed reason `writer-unused-dependency-setup`. This rejection may precede a precise undefined-name finding, so the host performs the read-only binding check for this specific failure as well. It retains both findings and only plans a replacement when the AST inventory proves a sole test method matching the Checker's owner and line. Multiple test methods, other structure failures or unavailable AST evidence cannot borrow that scope. If the names are valid, the original structure rejection remains in force. Execution skips the narrower helper-import selection for this combined failure because adding an import cannot fix unused setup.

The repair request names the unused local, explains that a local assignment does not replace the target module's global, and directs source-supported control and meaningful assertions after the real target call. It supplies no fixture value, expected result or call count. Complete rejected code and complete initializer declarations remain read-only evidence. The original request count, deadline, composition and downstream validation gates still apply.

For seed generation, explicitly empty and consistent parameter declarations on a module function omit optional parameter-fixture guidance and the default `types` import. Unknown, malformed, conflicting and class-bound declarations retain conservative guidance, including necessary constructor inputs. This relevance adjustment does not remove source evidence or prohibit a model from explicitly importing a source-supported test helper.

For a name-binding edit rejected as `invalid-edit-python`, the host independently inventories the exact extracted replacement before classifying it as a model syntax failure. The syntax kind and coordinates are bound to that replacement's hash, not to the raw provider envelope. Independent inventory limits or unavailability, and composition failures with parseable replacement code remain tool failures. Existing output diagnostics retain the completed request's wire shape and privacy-filtered excerpt (at most six lines/1200 characters, never a complete executable reply). Multiple fences remain ambiguous and rejected; diagnostics do not authorize choosing one, adding attempts or widening the scope.

Source-module bindings and test locals have different identities: replaying an initializer in a method does not replace the object used by the real target. Shared Writer guidance requires source-supported lookup control, restoration and assertions on the consumed dependency with the actual source binding. A neutral execution fixture repairs such a method, then proves that removing the target's side-effect call fails even though its return remains `None`. This checks controlled unit behavior, not real external resources or an independent business oracle.

Preliminary local `qwen2.5-coder:3b-instruct` diagnostic experiments with separately supplied system/user text returned the placeholder-derived owner `wrappers`; exact headers corrected the owner to `Cases`, but the body remained unchanged. A subsequent smoke test using the extension's actual `buildOllamaPromptEnvelope` instead failed with `unsupported-edit-response` despite the correct owner. None reached native execution. The preliminary experiments are not formal workflow evidence, and these separate smoke tests neither add product retries nor establish laboratory `codellama:13b` acceptance.

Mixed review findings and other general structure/fixture revisions still use the existing paths. Routing every operation through explicit local addition/replacement scopes remains part of generalization priority 2. Independent requirement-file/oracle input, measured capability adaptation and held-out real-model acceptance remain separate priorities. Local regression fixtures do not establish arbitrary-project or cross-platform support.
