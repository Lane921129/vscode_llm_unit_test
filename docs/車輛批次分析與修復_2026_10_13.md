## 根因與修訂

| 問題 | 可重播證據 | 本次修訂 |
|---|---|---|
| 匯入錯誤被遮蔽 | `get_vehicles`／`get_selected_plates` 匯入不存在的 `helpers`，unittest `_FailedTest` 被 runner 改報測試身分不符 | 保留真正匯入失敗；雙產物、當前摘要與 run 身分核驗後，只交 Writer 修訂；真正 identity／工具錯誤保持停止 |
| Writer 抄入通用範例 | 多個不相干目標產生同份 `example_target` 測試 | 正式提示移除可抄用完整範例，只保留文字設計指引；範例仍作內部回歸 |
| 傳輸抽取破壞程式 | 均一二空格外框在 `.trim()` 後變成第一行無縮排、後續 unexpected indent | 先正規化外框；保留 literal 位元組與完整尾端程式；多份候選不猜第一份 |
| 合法斷言被 AST 誤拒 | 方法內明確 target import 不被追蹤；無 return 的輸入物件狀態無相關性 | 方法詞法 import；來源直接屬性寫入＋fresh `SimpleNamespace`＋同物件真呼叫後斷言的窄版支持，不提供 expected |
| Reviewer 機械幻覺 | 把 `import unittest` 當無 target 的 patch、要求 target import 是 unittest module、稱合法 assertEqual 無效 | 使用同候選、已實跑且 AST 證明的事實要求一次重審；未知語意仍審，不自動批准 |
| length 重送只剩少量時間 | 舊批 1,536 tokens 約 46 秒，增加至 2,560 後只剩約 14 秒 | 首問前預留最多兩次單次額度；shared／target 硬上限不改；每次 HTTP／增容不續期 |
| 真實生成速度不足 | 新批一次約 291.7 秒仍在 1,536 tokens 被 length 中止，數值 metadata 顯示生成約 5～6 tokens／秒 | 以當次完整數值 timing 估算加長請求；時間不足不再送，記錄 available／estimated／原因碼；未知不推斷 GPU |
| 品質工具不適用 | 三個頂層目標被無條件送給只支援有序 instance 狀態的工具 | 頂層函式直接回不適用、不啟動 worker；數值 mutation probes 保留；空觀測報真實原因 |

仍有真實模型錯誤：漏掉 `DB_NAME`／datetime 等 import、patch 不存在的 module-global cursor、把 connection 替身設為字串、fetchall row 形狀不符、無來源或觀測依據的 `assertRaises(Exception)`、重複／無修改候選。這些不能靠放寬安全或品質 gate 算成成功；新提示與具體載入原因能改善修訂資訊，但仍須真模型重跑驗證。
