- 原結果沒有完整 Writer 回覆及可核對的啟動 build 身分，不能斷言它在重複、寫說明或一個測試尚未寫完，也不能精確指認實驗室所載入的 Git 版本。

## 目前優先問題與改動

| 問題 | 本次處理 |
| --- | --- |
| 最小種子仍混入完整套件要求，讓小模型解決互相競爭的範圍 | seed 改用獨立短角色契約，只寫一個方法與一次真實呼叫；保留必要來源、setup、隔離與觀測 |
| 一案生成仍附 optional 廣泛假說與設計材料 | structured seed 不附 optional topology、設計範例及 Analyst 假說；後續補測與修訂保留原流程 |
| 真實 3B 探測曾對同步目標寫出 `await`，正確的數值斷言仍執行失敗 | 依 AST 的 `is_async` 選擇一種種子呼叫指令；同步明示直接呼叫、禁止 await，非同步明示 async harness 與 await。未知 metadata 保留條件指令，不猜目標種類 |
| 只知道輸出 cap，不知道截斷內容形狀 | 保存 hash、字元及有界詞法統計，不保存 provider 原文，不採用部分程式 |
| 實驗室結果缺版本追溯 | manifest 在模型前保存擴充 ID、版本、模式與啟動 bundle mtime/hash；不冒充 Git commit |

目前最大的可觀測瓶頸是「模型先產出一個有效、可執行的 seed」。複雜 Mock／狀態物件與 Reviewer 的穩定性仍須後續驗收；這批沒有走到那些階段，不能拿它證明本次 Mock 或 Reviewer 再次失敗。小模型的方向是縮小每次工作，再根據實測缺口逐次新增；不靠降低品質門檻或按模型名稱放行。

## 驗證界線

固定回覆回歸驗證控制流程與真實 Python／突變工具，不代表真模型品質。另以本機既有 3B、2B 模型，對新建中性純函式使用真實受控 Trace 與正式 seed 提示／Ollama 傳輸／解析器，核對單一精確輸入與斷言並執行測試。實際結果與檢查數量記於本次 `CHANGELOG.zh-TW.md`。

單一 seed 實跑通過不代表 Analyst、Reviewer、完整覆蓋率、突變品質或任意 Python 專案全部通過；DGX／實驗室的原模型仍須 pull 新版後獨立重測。
