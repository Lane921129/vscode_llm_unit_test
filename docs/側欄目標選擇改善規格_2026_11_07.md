# PR #2a：側欄目標選擇改善（2026-11-07）

使用者在準備實驗室模型篩選時，回報了目前側欄的三個問題。本 PR 要在 PR #2 之前完成，因為之後的模型篩選與所有評估，都需要「同一組目標可以重複跑」。

## 使用者回報的問題

1. 選了檔案之後，函式下拉清單的排序很奇怪，不是照字母順序，很難找。
2. 一次只能選一個函式，不能累加。要跑 20 個函式就得手動選 20 次。
3. 在「批次測試來源」選好範圍之後，「測試目標」區塊沒有任何連動，還是顯示原本的單一檔案與函式選擇，看起來和批次範圍互相矛盾。

## 需求

### R1 排序

- 函式清單依名稱字母排序，不分大小寫。`Class.method` 依完整名稱排序；名稱相同時依檔案相對路徑排序。
- 檔案清單依專案相對路徑字母排序。
- 排序只影響顯示順序，不改變產品內部的目標身分。

### R2 多選與累加

- 測試目標區新增「目標清單」。
- 選擇檔案後，函式以核取方塊列出，提供「全選」與「全不選」。按「加入」後，勾選的函式加入目標清單。
- 可以切換到其他檔案繼續加入，達到跨檔案累加；重複加入的函式只保留一次。
- 目標清單可以個別移除、全部清空，並顯示總數。
- 執行時，以**批次方式**依清單順序跑所有目標。重用現有的批次 journal、報告、隔離與停止政策，**不另建新流程**。

### R3 批次範圍連動

- 在批次範圍預覽中勾選檔案後，測試目標區要顯示「已選檔案中的所有函式」，依 R1 排序、預設全部勾選，使用者可以取消個別函式。
- 畫面上不得同時出現與批次範圍不一致的單一檔案或函式選擇。

### R4 匯出與匯入目標清單

- 目標清單可以匯出成 JSON，格式與 `D:/read/專題/test/eval_screening/targets.json` 相同：

  ```json
  {"version": "eval-screening-v1", "targets": {"相對路徑.py": ["函式名稱", "..."]}}
  ```

- 可以匯入同格式的 JSON。匯入時檢查每個檔案與函式是否存在；不存在的項目要列出並略過，不能默默忽略。
- 目的：讓不同模型能跑**完全相同的一組目標**。

### R5 狀態保存

- 目標清單依專案根目錄保存在 workspace state，重開 VS Code 後保留，做法比照現有的 `batchScopeStateKey`。

## 不變的部分

v1 流程、品質門檻、提示詞、停止政策、隔離與突變量測全部不變。`src/orchestrator.ts` 只能加入「接收明確目標清單」的最小分支。

## 可能修改的檔案

- `src/ui/webviewContent.ts`、`src/ui/SidebarProvider.ts`：UI 與訊息處理
- `src/pipeline/targetList.ts`（新）：排序、去重、驗證、JSON 匯出與匯入、狀態保存
- `src/pipeline/batchScope.ts`：與批次範圍連動
- `src/orchestrator.ts`：批次入口接收明確目標清單（最小分支）

## 驗收

- 單元測試：排序（含大小寫與 `Class.method`）、去重、加入與移除、JSON 匯出入往返、匯入時不存在的項目、狀態保存與還原。
- Webview 測試：`npm run test:webview` 通過。
- 整合測試：用一份含 2 個檔案、3 個函式的目標清單執行批次，必須剛好依清單順序跑這 3 個目標，`batch_manifest.json` 記錄的目標與清單一致。
- 用 `D:/read/專題/test/eval_screening/targets.json` 匯入，必須得到 26 個目標，且沒有任何不存在的項目。
- `npm run test:fast`、`npm run test:golden` 通過，golden 快照不變。
