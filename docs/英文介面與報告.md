# 英文介面與報告

在側欄選擇 `English`，或設定 `llmUnitTest.language=en`。`auto` 跟隨 VS Code 顯示語言；明確選擇英文時，不受 VS Code 的中文顯示語言影響。

## 本次修正

- 側欄新增項目改用字典：Cloud 設定、驗證模式、Tier 說明、初始化入口、儀表板、提示文字及動態結果卡。
- 資料夾選擇、連線資格、相依掃描、安裝清單與確認按鈕使用同一語言設定。安裝的確認條件及隔離限制不變。
- 新產生的執行訊息、結果標頭、Tier 降級摘要、修復診斷、單函式與批次報告可使用英文。scorecard 同時辨識新英文及既有中文報告，仍核對原始執行證據；起始 Tier 不能取代保留候選 Tier，英文失敗報告不能因舊分數而通過。
- 從 VS Code 設定頁變更語言會更新側欄。若工作區已有語言設定，側欄會更新該設定，避免只改全域值後仍被覆蓋。
- 執行中的報告固定使用啟動時的語言，側欄延後重載至執行結束，避免清掉中止按鈕及目前狀態。新執行使用新的語言。

## 顯示範圍

VS Code 的命令面板、活動列標題及設定頁由 VS Code 載入 `package.nls.json`／`package.nls.zh-tw.json`，跟隨 **VS Code 自身的顯示語言**。側欄的語言選項只控制擴充套件自己產生的介面、通知與新報告。語言選單保留「繁體中文」自稱，方便使用者切回。

既有報告不會重新翻譯。使用者檔名、受測程式碼、模型回覆、Python 原生輸出及錯誤證據保留原文；其中出現中文不代表英文設定失效。翻譯只套用到程式中明確登錄的框架訊息，插入的證據不作搜尋取代。

## 驗證方式

回歸測試涵蓋英文側欄完整產物、真正執行的 Webview 腳本、安裝清單腳本、雙語字典欄位與參數一致性、設定覆蓋與即時刷新、執行中語言固定、階段／修復／失敗分類，以及英文 scorecard。完整品質整合測試使用真實隔離 Python、coverage 與突變，模型回覆使用固定替身；另驗證英文 execution 報告仍明示未執行突變。

這些本機驗證不代表實驗室模型整批通過。實驗室更新後請重新建置並重開 F5 的 Extension Development Host，選擇 `English` 再產生新結果。
