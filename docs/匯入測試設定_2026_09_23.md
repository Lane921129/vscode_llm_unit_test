# 不修改受測原檔的匯入測試設定

## 建議入口：先檢查，再預覽套用

在側欄選擇受測專案後，按 **「檢查模組載入／初始化設定」**。工具會逐一預檢有可選測試目標的模組，先讀 AST，再於隔離程序載入；不呼叫模型、不安裝套件。沒有可選目標的檔案仍可能作為相依在載入時受檢，這不是完整應用或所有延遲匯入的驗證。

若實測匯入被目錄建立阻擋，工具開啟設定建議，列出受測根目錄、正確相對來源及來源雜湊。確認 **「套用此清單並重新檢查」** 後，保存到 VS Code 使用者的測試工具設定，重新預檢。關閉預覽不套用；來源或設定在預覽期間改變則拒絕。既有設定項目會保留；不在受測專案內新增 `.vscode` 或改寫原始檔。

自動建議目前只涵蓋觀測到 `os.mkdir` 阻擋之來源的模組頂層 `Path.mkdir` 替身；直接 `os.mkdir`、函式內初始化與其他操作不會因此獲得放行。即使已套用建議，也必須看重新預檢結果；支援之外的情況保持受阻。

設定精靈同時保存 `llmUnitTest.importFixtureRoot`，避免切換專案時把同名來源套到另一個專案。既有手動清單在未設定 root 時仍相容；若清單原本是以內層專案為根，切換成 `all_test` 時，必須改用以 `all_test` 為基準的完整相對路徑。根目錄不符時會拒絕套用，不能宣稱初始化已處理。

整批測試也會在模型請求前預檢。若有模組受阻，先開啟 `preflight/import_check.md`；關閉提示就停止，目標維持未完成。只有選擇 **「繼續測試並記錄失敗」** 才繼續，環境受阻的目標仍然失敗。若只想先處理環境，關閉提示後使用上述設定入口。

### 套件存在但 API 不存在

`dependency-api` 表示已載入的模組沒有程式要求的屬性，例如本次實驗室的 `flet.app`。它與缺套件不同；工具列出模組及 API，要求核對實際載入來源、版本與專案相依宣告，不會用空殼 API 或猜測版本偽裝通過。套件版本仍須在實驗室選用的 Python 中處理；初始化替身不能修復這類不相容。

### 判讀結果

報告最上方與結果卡各自標示最終狀態。只有同一份證據完整達標、符合審查政策且最終狀態為 passed，才標示綠色「完整通過」。分數改為中性色，階段 passed 明示僅該步驟成功。批次摘要區分完整通過、環境受阻、失敗、略過／未評分及未完成；不以 completed 或 100% 代替驗收。

## 使用情境

受測模組在 import 時建立目錄、讀取設定或啟動介面，會在測試生成前觸發執行隔離。`llmUnitTest.importFixtures` 可明確宣告這些初始化相依的測試替身；預設空清單保留嚴格匯入。

原始來源檔案不會改寫，也不會刪除 AST 語句。模組照原本方式執行，只有符合來源與操作範圍的外部呼叫被模擬。匯入後的函式呼叫仍使用原隔離規則；不能因此直接寫正式檔案或連線正式資料庫。

## 車輛管理的設定

上方「受測專案目錄」選擇**內層**車輛管理資料夾。把以下欄位合併到 VS Code 的工作區設定；不要建立在受測原始碼裡，也不要覆蓋其他設定：

```json
{
  "llmUnitTest.importFixtures": [
    { "file": "config.py", "mkdir": true },
    { "file": "main.py", "mkdir": true, "entryPoints": ["flet.app"] },
    { "file": "車輛管理測試/main.py", "mkdir": true, "entryPoints": ["flet.app"] },
    { "file": "車輛管理測試/old backup/main_backup.py", "entryPoints": ["flet.app"] }
  ]
}
```

如果只測正式版，保留前兩筆即可。`file` 必須是受測根目錄內實際存在的相對 Python 路徑；切換成其他專案時，也要切換工作區設定或清空此清單。舊備份仍須有正確的本地 import 路徑，這項功能不會假造缺少的模組。

若設定檔會讀取真實 `config.ini`，請替該檔案提供測試內容，例如：

```json
{
  "file": "config.py",
  "mkdir": true,
  "configFiles": {
    "config.ini": "[PATH]\nDATA_DIR = test-fixture-data\n"
  }
}
```

這是替換前述第一筆規則，不是新增同名規則。內容只填測試資料，不放真實憑證。此設定不會真的建立 `test-fixture-data`；後續函式若需檔案或資料庫行為，仍須在單元測試中明確 mock。

爬蟲以 `Web_Spider` 為受測根時，設定改為：

```json
{
  "llmUnitTest.importFixtures": [
    { "file": "config/settings.py", "mkdir": true }
  ]
}
```

## 支援範圍

- `mkdir`：只模擬所宣告來源檔的**模組頂層** `pathlib.Path.mkdir`，回傳 None，不執行真實建立目錄。
- `configFiles`：只針對所宣告來源旁的具名 `.ini`，在模組頂層用受控 `Path.exists` 與 `ConfigParser.read` 提供測試文字；不放寬任意 open/read。
- `entryPoints`：只模擬所宣告來源頂層呼叫的外部函式，回傳 None；不執行 callback，不替換受測函式、應用本地函式或類別。
- 未宣告來源、一般函式內、helper 內的操作不會獲得這些替換。即使保留了 mock 的函式別名，也不能把初始化授權延伸到函式執行。
- 套件本身仍須存在並正常匯入；不偽造 Flet 或其他缺少的套件。

如果原始程式把初始化放在 helper 中，或依賴未支援的動態入口，工具會保留具體阻擋原因。不能宣稱所有第三方應用都能在無設定下自動測試。

## 各階段的一致性

同一目標會快照測試設定及相關來源雜湊，套用到預檢、每個 Trace worker、正式 unittest／coverage 和內建突變測試。設定雜湊列入預檢快取鍵；來源變更會拒絕沿用舊設定。

使用匯入 fixture 時採用內建突變引擎，讓 baseline 與 mutant 都走同一個受控執行器。突變副本會重新綁定同一份設定；沒有改寫正式來源。未符合這項契約的外部突變引擎不會被用來提供分數。

每次結果目錄會保存 `import_fixtures.json`。知識紀錄及正式報告標示其 ID；預檢事件和測試執行事件記錄實際模擬的來源、操作與行號。這些結果僅在該份測試條件下成立，不等於真實 GUI 啟動或正式儲存環境已驗證。

重現生成的 unittest 時，使用同一個 Python、相同 import 路徑及這份 JSON。例如在結果目錄使用 PowerShell：

```powershell
$env:LLM_UNIT_TEST_IMPORT_FIXTURES = Get-Content -LiteralPath '.\import_fixtures.json' -Raw
# 將 python、runner 路徑及 test_module 換成本次結果對應值。
& python '工具專案\python_scripts\generated_test_runner.py' test_module
Remove-Item Env:LLM_UNIT_TEST_IMPORT_FIXTURES
```

不要把帶有這份測試環境條件的 unittest 當成可不帶設定直接啟動的應用驗證。

## 相依檢查

`pip check` 每次環境準備都會執行，不再只在有新安裝時檢查。錯誤報告保留安全的套件名稱與版本條件，並在安裝失敗時指出失敗項目。私有套件來源、憑證及任意 pip 原文仍不輸出。

目前 Python >= 3.12 使用 coverage >= 7；Windows 使用內建突變引擎。如果共用 Python 留有要求 coverage < 6 的舊 mutatest，應整理該環境或另建本專題的虛擬環境。工具不會自動移除共用環境中的套件。

### 實驗室已回報的 mutatest／coverage 衝突

這次回報證明 Flet 的頂層套件已可找到，但整個 interpreter 的相依仍不相容。重按安裝不會移除舊 mutatest；也不應為了它把 Python 3.13 所用的 coverage 降到 5。

如果這個 Python 只供目前測試工具使用，且沒有其他工作需要 mutatest，可在實驗室 PowerShell 執行下列步驟。第一行會先列出待移除套件並要求確認；只移除舊測試工具，不修改受測程式：

```powershell
& 'C:\Users\ncyu_stu\AppData\Local\Programs\Python\Python313\python.exe' -m pip uninstall mutatest
& 'C:\Users\ncyu_stu\AppData\Local\Programs\Python\Python313\python.exe' -m pip check
```

若此 Python 有其他用途，請改在**測試工具的資料夾**建立獨立環境。先確認 `.venv-vms` 尚未存在，避免沿用已有衝突的環境：

```powershell
& 'C:\Users\ncyu_stu\AppData\Local\Programs\Python\Python313\python.exe' -m venv .venv-vms
& '.\.venv-vms\Scripts\python.exe' -m pip install -r requirements.txt
```

把 `llmUnitTest.pythonPath` 指向這個新環境的 `Scripts\python.exe` 完整路徑，再選內層車輛管理目錄，執行「檢查此專案相依」並確認安裝清單。若原專案有要求套件版本，依原有宣告安裝；安裝成功仍需通過正式匯入預檢。最後 `pip check` 應顯示 `No broken requirements found.`，否則依報告處理剩餘衝突。

虛擬環境預設隔離系統套件；`pip check` 只檢查相依宣告是否一致，不代表 GUI 或應用執行已成功。參考 [Python venv 文件](https://docs.python.org/3/library/venv.html)與 [pip check 文件](https://pip.pypa.io/en/stable/cli/pip_check/)。

本地匯入根不明的模組會列為「本地匯入待確認」，不能當成 PyPI 同名套件補裝。請選擇正確的子專案／載入範圍。
