# 結果匯出與短路徑

## 為什麼 coverage 檔會顯示名稱過長？

`coverage_4a582379-61d9-4d74-9175-ac8ea9f00ed6.json` 本身是 50 個字元。Windows 的部分檔案 API 與 Shell 受完整路徑限制影響，計算包含磁碟機、全部上層資料夾與檔名；程式能寫入不代表檔案總管一定能壓縮或搬移。啟用長路徑也需要應用程式配合。[Microsoft 路徑限制文件](https://learn.microsoft.com/windows/win32/fileio/maximum-file-path-limitation)

## 新結果的命名

- 一批結果內的目標資料夾改為單層短名稱，例如 `t_database_update_user_0123456789`，不再複製多層來源目錄。
- `target.json` 保留完整來源路徑、限定函式名稱與完整來源鍵雜湊；批次清單持續記錄每個目標的實際報告位置。
- `coverage_001.json` 與 `invocation_001.json` 成對保留；Trace 使用 `trace_001.jsonl`。不同執行仍有完整 UUID 記錄在證據內容中，檔名編號不是身分驗證依據。
- 可執行快照使用 `exec_<16碼>.py`，完整 64 碼 codeHash 留在 JSON 並於讀取既存檔案時核對；若短名稱衝突或內容損壞，拒絕覆寫。
- 重跑另配資料夾／檔名，保留原證據。若使用者選的輸出根本身過長，會請使用者改用較短位置；不修改 Windows 登錄設定。

舊結果不會自動重新命名，也不會被新輸出覆寫。

## 把既有結果透過 RDP 帶回

在**實驗室電腦**、測試工具專案目錄執行以下 PowerShell 指令，把第一個路徑替換為要傳送的那一批結果：

```powershell
python .\python_scripts\export_results.py "C:\結果\all_test_2026_09_24_14_05" "$env:USERPROFILE\Desktop\r0924.zip"
```

此工具只使用 Python 標準庫；若 `python` 不在 PATH，改用已選 Python 的完整路徑呼叫。ZIP 目的地必須在來源結果資料夾外，而且不能已有同名 ZIP；工具不覆寫舊壓縮檔。

完成後：

1. 透過 RDP 複製桌面的單一 `r0924.zip`。
2. 收件端選短的解壓縮目錄，例如 `C:\r`，避免再增加長目錄前綴。
3. 開啟根目錄的 `batch_summary.md`、`batch_manifest.json`；單函式匯出則開啟 `final_report.md`。
4. 查看 `_transfer.json`：`missingReports` 若非空，表示來源本來就缺報告；需要回到原電腦補齊，壓縮不會重建缺失證據。`extractionDirectoryBudget` 是以完整路徑 240 字元為保守目標所剩的解壓縮根目錄長度，並非所有壓縮工具的保證。

ZIP 直接從所選結果目錄的內容開始，**不再包一層很長的批次資料夾名稱**。所有既有相對路徑及原檔 bytes 保留，新增 `_transfer.json` 記錄逐檔 SHA-256 與缺報告資訊；匯出後逐檔解壓讀取並核對雜湊。不跟隨符號連結或 junction，來源在匯出期間變動則停止並移除本次未完成 ZIP。

請在該批次停止寫入後匯出。舊證據內的絕對來源位置仍指向原執行環境；壓縮成功不代表 GUI、模型、測試品質或在新電腦重跑已驗證。
