## 正式執行隔離

新增 `python_scripts/generated_test_runner.py`，正式 unittest、coverage、獨立 Trace baseline、內建 mutation baseline／mutant 都使用相同入口。外部引擎的 runner 亦改用此入口，由工具記錄每次執行的開始、結束與隔離狀態。缺少紀錄、未完成或觸發阻擋均拒絕分數，不能讓外部引擎把安全阻擋當作 killed 後回報通過。

- 真實檔案讀寫、shell／子程序、網路連線與非隔離 SQLite 在執行時阻擋；標準 import 與 traceback 所需的來源讀取保留。
- 明確 dependency mock、mock_open、私有 `:memory:` SQLite 與 asyncio 標準 event-loop plumbing 可用；不允許共享 URI、ATTACH／VACUUM INTO、extension loading 或替換 authorizer。
- 阻擋記錄持續到該執行結束，即使目標吞掉例外、unittest 捕捉例外或試圖提前結束，也不改成通過。隔離診斷不提供輸出／例外 oracle。
- coverage 的啟動與寫檔由工具在 guard 外完成。Python 3.13 traceback 的合成 `<unknown>` 來源讀取只放行對應標準 traceback／AST 路徑，應用程式直接讀檔仍禁止。
- 內建 mutant 的隔離違規記 ERROR，不記 KILLED；出現工具／隔離 ERROR 時整輪不產生品質分數。測試 fixture 隔離問題交 Writer，不猜測 Bug Fixer 方法。

這是生成碼 AST gate 之外的執行防護，不是對惡意原生 extension 的作業系統 sandbox。環境預檢原有的 import 副作用阻擋仍保留；這次沒有把應用初始化副作用自動放行。

## 角色契約

- `review-v7`：完整測試仍提供，但空白與註解沒有可選 ID，另列 `VALID_TEST_LINE_IDS`。拒絕模板回聲、明顯無關的 unittest import／assertion 定義行引述，以及帶引號的 decorator／mocked target 修改建議；不能將拒絕 finding 刪掉後偽裝成空問題通過。
- `quality-task-v3`：仍是每輪一個實測 focus、最多一項情境，共用 deadline 的格式補正最多一次。移除會被複製的 JSON 模板文字，拒絕無內容的模板／None 字串，要求明確 input、object state 或 mock 回傳配置。具體的 `value=None` 實驗仍可提出，但預期值必須再執行驗證。
- `bug-fix-v4`：正式請求改為一段 Python fence，內含最多三個必要 import 與唯一失敗方法，減少把多行 Python 放進 JSON 字串造成的轉義錯誤。其他測試、fixture、decorator 與 signature 由 host 保留，仍走 Python AST 範圍檢查；舊 JSON 只保留解析相容性。
- Writer 增加精簡 fixture 檢查：必要建構參數、可到達目標分支的狀態、mock 使用點與每層實際回傳配置；禁止用裸 MagicMock 或猜測例外填滿案例數。
- 模型資格升為 `python-unittest-v5`，Reviewer probe 使用 JSON、Bug Fixer probe 使用文字 Python；本機、Cloud、Custom 均遵循角色輸出格式，不依模型名稱分派。先前資格不會被自動升級。

上述 parser 改善能拒絕已知錯誤，不能保證任意模型語句都正確。新提示詞是否提升 CodeLlama 13B 或 1B～5B 的實際成功率，仍需實驗室重新生成驗證。
