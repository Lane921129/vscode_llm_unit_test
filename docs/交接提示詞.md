# 交接提示詞

這個專案會輪流交給 Claude Code、Codex、Antigravity 執行，交接狀態記錄在 `docs/HANDOFF.md`。

- 每次開新對話：貼 **A（共用開場）**，再加上該 agent 的一行（**C**）。
- 額度快用完，或你想換 agent 時：貼 **B（結束交接）**。

---

## A. 共用開場（每次都貼）

```
你是接手這個專案的開發 agent。這個專案會輪流交給 Claude Code、Codex、Antigravity 執行，交接只靠倉庫中的文件，不靠對話紀錄。

【開始前依序執行】
1. 完整閱讀 docs/HANDOFF.md。
2. 閱讀 docs/三週改版架構_2026_11_04.md 的第 0 節，以及第 9 節中「目前進行中 PR」那一列。需要細節時，搜尋對應章節，不要整份讀。
3. 用 git branch 和 git status 確認目前在 HANDOFF 指定的分支，且工作區狀態與 HANDOFF 描述一致。若不一致，先停下來回報，不要清除或覆蓋未提交的變更。
4. 如果你有 AOCI 工具：依 AGENTS.md 呼叫 aoci_rules，再以最小 scope 呼叫 aoci_overview。沒有 AOCI 工具就跳過，不要假裝有呼叫。
5. 找符號優先用 CodeGraph（若可用）或 rg。不要整檔讀 src/orchestrator.ts、PROJECT_RULES.md、ARCHITECTURE.md、CHANGELOG.zh-TW.md。

【工作規則】
- 只做 HANDOFF「下一步」清單中的項目，並依順序執行。不要跳到其他 PR，也不要做清單以外的改善。
- 每完成一個步驟、且相關驗證通過，就在 PR 分支上 commit（中英雙語訊息），並立刻更新 HANDOFF：勾掉該步驟、填入驗證結果、寫明下一步。
- 長時間的測試（test:integration 約 37 分鐘）在背景執行，輸出導到 log/，只讀摘要（通過與失敗數、失敗的測試名稱）。
- HANDOFF 中已記錄通過的驗證，如果之後沒有改動相關程式，就不要重跑。
- 遇到 HANDOFF 第 0 節沒有涵蓋、需要使用者決定的事（例如改變通過標準、重試次數、預設行為或提示詞內容），寫進 HANDOFF 第 3 節「需要使用者決定」後結束工作。
- 不要為了讓測試通過而更新 golden 快照；有差異就記錄並停下。
- 只有 HANDOFF 寫明使用者已驗收該 PR，才可以 push。
- 文件與 commit 訊息的中文部分使用繁體中文。

【額度管理】
- 如果預估剩餘額度不夠完成下一個步驟，就不要開始它。
- 額度快用完時，立刻執行以下「結束交接」：
  a. 修改能通過驗證就正常 commit；不能通過就用 wip(prNN): 前綴 commit，並在 HANDOFF 寫清楚哪裡沒完成、哪個測試失敗，以及下一個 agent 應從哪個檔案、哪一步開始。
  b. 更新 HANDOFF 的 PR 進度表、下一步清單，並在工作階段紀錄加一筆（agent 名稱、時間、做了什麼、commit hash）。
  c. 有 AOCI 工具且本 PR 已完成：呼叫一次 aoci_maintain。沒有 AOCI 工具，或 PR 尚未完成：在 HANDOFF 第 4 節「AOCI 待辦」記一筆。

【結束時】用 5 行以內告訴我：完成了什麼、驗證結果、commit hash、下一步、是否需要我決定。
```

## B. 結束交接（額度快用完或想換 agent 時貼）

```
現在停止新的工作，執行 HANDOFF 的「結束交接」：
1. 把目前的修改 commit 到 PR 分支（未通過驗證就用 wip(prNN): 前綴）。
2. 更新 docs/HANDOFF.md：PR 進度表、下一步清單、工作階段紀錄，並寫明下一個 agent 應從哪個檔案、哪一步開始。
3. 用 5 行以內回報。
```

## 使用建議

- **AOCI 收尾交給 Codex**：PR 由 Claude Code 或 Antigravity 完成時，之後開一個很短的 Codex 對話，只處理 HANDOFF 第 4 節的 AOCI 待辦，花不了多少額度。
- **長測試交給額度最充足的 agent**：`test:integration` 要跑 37 分鐘。
- **每次換 agent 前**，自己快速看一下 `docs/HANDOFF.md` 的「下一步」是否合理。這是你掌握進度最快的方式。
