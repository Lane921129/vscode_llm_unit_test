# 修復失敗診斷紀錄

本次解決 2026-09-21 批次中 Bug Fixer 已回覆、卻只留下通用錯誤的追溯缺口。接受規則、模型契約、重試額度與降階方式維持原有行為；這不是格式容錯或模型成功率改善的驗收。

## 三個閱讀入口

- `role_events.jsonl`：每次格式拒絕、修復範圍拒絕與重複候選都即時落盤。事件本身含 runId、sourceHash、sequence、loop、time、stage；detail 含 attempt、角色契約、原因碼與可用的耗時。
- `function_knowledge.json`：`firstRepairFailure`、`lastRepairFailure` 與 `repairFailureCounts` 保留具體修復失敗，不會被後續 pipeline 通用錯誤覆蓋；原 firstFailure／lastFailure 仍保留各自用途。
- `final_report.md`：即時顯示中文原因、回覆結構、原測試未修改與已驗證基線狀態；`repair-routing` 說明下一步是繼續修訂、降階或停止。原測試未修改不代表原測試已通過。

`run_manifest.json` 加入 `repairDiagnosticsVersion: repair-diagnostics-v1`。版本與角色／建置資料可對照同目標紀錄；這是新增診斷版本，沒有升級模型資格契約。

## 原因分類

| 檢查階段 | 原因碼範例 |
| --- | --- |
| response-format | empty-response、missing-code-fence、extra-text、multiple-code-blocks、class-wrapper、missing-test-method、method-name-mismatch、multiple-test-methods、import-limit、invalid-import、invalid-json-replacement |
| repair-scope | candidate-syntax、import-conflict、import-star、import-removal、no-method-change、unrelated-method-change、outside-method-change、scope-tool-error、scope-result-invalid |
| candidate-deduplication | repeated-candidate、repeated-failure |

例如模型在單方法 Python fence 前加入解說時，會保存 `extra-text`、回覆長度與結構統計、responseHash、previousTestHash，並說明原測試未修改。Python AST 查出新 import 覆蓋既有 binding，則保存 `import-conflict`，不再和「超過三個 import」混用一個訊息。

回覆結構統計包括完整程式區塊、class、test_ 方法、import 數量及區塊外內容。這些是詞法線索，不是 AST 正確性證明。解析器一次回傳首先確定的拒絕原因，不聲稱窮舉回覆內所有問題；Legacy JSON 仍由原相容 parser 驗證。

## 隱私與限制

新增診斷不保存完整模型回覆、不列出模型自訂方法／匯入名稱、不複製任意 provider body 或工具 stderr。以固定原因碼、受控中文說明、數量、布林值及 SHA-256 追溯；原有測試候選與其他角色產物仍依既有規則保存。
